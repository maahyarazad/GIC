# Implementation Plan: Manage Presentations — upload presentations under events

**Branch**: `011-manage-presentations-upload` | **Date**: 2026-10-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/011-manage-presentations-upload/spec.md`

## Summary

Add a **Manage Presentations** dashboard section where signed-in members upload presentation files
(≤ 50 MB, with a live upload-progress loader) and attach each to an event (one event → many
presentations). Files are stored on disk in `file_storage` with metadata in a new `presentations`
collection, and are served **only** through an authenticated controller route — never the public
`/uploads` static mount. The member Events view gains a presentations **badge** (reusing the
existing `event-status-badge` family) and an event modal listing the event's presentations, each
opening in a new tab via the protected route. Newsletter authors reference a presentation's
protected URL through the existing Quill link tool.

## Technical Context

**Language/Version**: TypeScript (Node.js, backend) + TypeScript React (frontend)

**Primary Dependencies**: Backend — Express 4, tsoa (controllers → auto-generated `src/routes/routes.ts`), Mongoose 9 + MongoDB driver (`getCollection`), `multer` (memory storage), `jsonwebtoken` (cookie auth), `mime-types`. Frontend — React + Vite (SSR), `axios`, `quill` 2, Bootstrap, SCSS.

**Storage**: MongoDB (metadata, new `presentations` collection) + local disk `file_storage/` (file bytes). Served via protected controller endpoint, not `express.static`.

**Testing**: Manual QA via quickstart scenarios (repo has no automated test runner wired for these controllers); optional controller-level checks if a harness is added.

**Target Platform**: Web (SSR React client + Express API), same deployment as existing app.

**Project Type**: Web application (backend `src/`, frontend `ui/`).

**Performance Goals**: Upload of a 50 MB file completes with visible progress; view route streams the file with correct content type. No new heavy processing.

**Constraints**: 50 MB hard upload cap enforced server-side (multer `limits.fileSize`). Protected view route must never fall back to the public `/uploads` mount. Do not hand-edit `src/routes/routes.ts` (tsoa-generated) — add decorated controller methods and regenerate.

**Scale/Scope**: Small — one new collection, one new controller (upload + list + view + delete), ~2 new UI areas (Manage Presentations section, event modal list) + 1 new badge tone + newsletter link reuse.
